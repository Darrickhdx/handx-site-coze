# 本地预览运行层重构规格

## Problem Statement

站主希望网站在继续增加访客互动、站主操作和研究投影时，仍然能够安全、清晰地维护。当前这些能力与 Next.js 启动、请求分派、私密数据、安全规则和研究代次校验集中在同一个服务入口中。虽然现有行为已经通过验证，但任何修改都需要同时理解大量无关细节，容易造成权限、隐私、评论审核或研究投影边界的回归。

本次工作同时承担一个方法论实验：验证 Matt Pocock 的领域建模、深模块、规格、纵向任务、TDD 和双轴审查流程，是否能比直接修改代码产生更清楚、可验证、可复用的结果。

## Solution

建立一个统一的“本地预览运行层”深模块。它通过一个 Node HTTP 请求处理器提供全部本机运行能力，并隐藏访客互动、站主操作、研究投影、安全策略、私密存储和启动门禁。服务组合根只负责准备 Next.js、创建运行层并监听回环地址。

本次重构严格保持现有外部行为，不新增网站功能、不修改公开内容、不扩大部署范围。真实 HTTP 行为是主要测试 seam；测试通过实际请求观察状态码、响应内容、响应头、权限和数据可见性，不依赖内部文件组织。

## User Stories

1. 作为普通访客，我希望重构后仍能正常浏览所有网站页面，以便工程调整不会破坏阅读体验。
2. 作为普通访客，我希望统计事件仍只接受合法字段和合法来源，以免意外收集超出声明范围的数据。
3. 作为普通访客，我希望私密留言仍默认进入待处理状态，以免留言被自动公开。
4. 作为小说读者，我希望评论仍然先审后显，以免未审核内容直接出现在章节页面。
5. 作为小说读者，我希望已撤回的评论立即从公开结果消失，以免失效内容继续传播。
6. 作为小说读者，我希望不同章节的评论保持隔离，以免评论出现在错误章节。
7. 作为站主，我希望只有持有本机管理员令牌时才能读取留言箱，以免私密联系方式泄漏。
8. 作为站主，我希望只有获准请求才能审核评论，以免外部页面伪造审核操作。
9. 作为站主，我希望评论日志损坏时系统停止公开评论，而不是继续展示不可信状态。
10. 作为站主，我希望私密目录和文件继续保持严格权限，以免本机其他普通进程误读敏感内容。
11. 作为站主，我希望语料命中只返回定位性元数据，以免私密正文或本机路径进入浏览器。
12. 作为历史研究读者，我希望研究投影继续绑定到同一批准代次，以免看到混合的新旧数据。
13. 作为历史研究读者，我希望研究投影保持只读且不自动生成新事实，以免派生页面被误认为史料。
14. 作为项目维护者，我希望所有本地运行能力由一个清晰入口提供，以免在服务入口重复维护路由和安全规则。
15. 作为项目维护者，我希望新增运行能力时只修改运行层内部和相应 HTTP 测试，以减少散落修改。
16. 作为项目维护者，我希望测试只依赖可观察行为，以便内部文件重新组织时测试仍然有效。
17. 作为项目维护者，我希望启动门禁失败时服务拒绝监听，以免不安全状态被误当成可用网站。
18. 作为项目维护者，我希望未识别的网站请求仍准确交给 Next.js，以免运行层吞掉普通页面或 404。
19. 作为项目维护者，我希望意外错误保持安全的通用响应，以免把私密路径、令牌或内部细节返回给浏览器。
20. 作为项目维护者，我希望实验产生规格、任务、决策、测试和复盘证据，以便判断这套 skills 是否值得用于后续新项目。
21. 作为未来的新项目发起人，我希望得到一套经过真实项目验证的采用指南，以便知道什么时候使用哪些 skills。
22. 作为站主，我希望整个实验保持仅本机运行且不发布公网，以免方法论试验绕过既有发布授权门禁。

## Implementation Decisions

- 本地预览运行层是一个深模块，外部只暴露创建完整 Node HTTP 请求处理器的工厂。
- 工厂接收项目根目录、私密运行目录、回环监听信息、部署环境和 Next.js fallback。
- 运行层负责所有站点级私有缓存与禁止抓取响应头，避免调用方遗漏。
- 运行层内部固定分派现有八个本地运行接口和四个研究投影；不建立公开路由注册系统。
- 访客互动、站主操作和研究投影是领域分类及内部局部性分组，不机械变成三个公开接口。
- 未识别请求以及研究投影的非 GET/HEAD 请求继续交给 Next.js，保持现有行为。
- 现有 URL、方法、状态码、错误标识、响应字段、`Allow`、认证提示、HEAD 语义和错误检查顺序属于冻结合同。
- Host、Origin、管理员令牌、请求体上限、限流、容量、文件权限、XSS 转义和 fail-closed 行为保持不变。
- 研究投影继续在启动时一次性读取、验证并冻结；混合代次、运行数据与编译数据不一致或发布门禁开启时拒绝启动。
- 文件系统使用真实临时目录进行测试，不建立只有一个实现的文件系统 port。
- Next.js fallback 是真实内部 seam：正式运行使用 Next adapter，运行层 HTTP 合同测试使用最小 fallback adapter。
- 不为时钟、随机数、加密、日志或评论存储建立没有第二个真实 adapter 的公开抽象。
- 评论存储可以保持内部模块，但不把其单实现接口提升为运行层的外部 seam。
- 服务入口最终只负责读取启动配置、准备 Next.js、创建运行层、监听端口和进程生命周期。
- 本次不创建 Sites 托管项目；Sites 只用于既有网站的本地 capability-path 构建和预览交接，服从禁止部署门禁。

## Testing Decisions

- 主要 seam 是真实 Node HTTP：通过临时回环端口向运行层发送实际请求。
- 快速合同测试使用真实临时文件目录和最小 fallback adapter，不 mock 内部模块。
- 现有全站冒烟测试继续作为最高系统 seam，覆盖 Next 页面、运行接口、研究投影、权限、评论生命周期和启动门禁。
- 重构前补齐研究投影的代次响应头、GET/HEAD 一致性、非法方法、认证提示及 fallback 行为。
- 测试名称使用 `CONTEXT.md` 中的“本地预览运行层”“访客互动”“站主操作”“研究投影”术语。
- 测试只断言外部可观察结果，不断言内部函数调用、文件名、路由表结构或类实例。
- TDD 以一个失败的 HTTP 合同测试开始，每次只完成一个纵向行为切片。
- 实施期间持续运行相关合同测试和类型检查；最终运行完整验证、生产构建和全站冒烟。
- 启动失败行为使用真实进程或工厂创建结果验证，不把启动门禁伪装成普通 HTTP 响应。
- 双轴审查分别检查项目标准与本规格，避免“代码漂亮但实现错误”或“实现正确但违反标准”互相遮蔽。

## Out of Scope

- 新增、删除或重命名网站页面和接口。
- 修改页面视觉、文案、信息架构或导航。
- 修改统计事件词表、留言字段、评论规则或管理员权限。
- 改变研究来源、主张、节点、关系或历史事实边界。
- 修复本次发现但不影响模块抽取的既有产品行为。
- 支持 Edge Runtime、Cloudflare Workers、Serverless 或公开部署。
- 引入数据库、远程存储、第三方认证或外部分析服务。
- 建立通用插件系统、声明式路由 DSL 或假想 adapter。
- 推送 GitHub、创建线上 Issues、创建 Sites 项目或发布生产版本。
