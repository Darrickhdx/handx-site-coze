## 结果

实验项目：Handx web0.1 的“本地预览运行层”  
结果：**95/100，全部硬门禁通过。**

核心变化：

- `src/server.ts` 从 1573 行收缩到 35 行，只保留配置、Next.js、运行层创建与监听生命周期。
- 新的唯一外部入口是 `createLocalPreviewRuntime(options): RequestListener`。
- 8 个本地运行接口、4 个研究投影、Next fallback、安全响应头、启动门禁和安全错误处理都由运行层承担。
- 新增 9 个真实回环 HTTP 合同；生产构建和完整 smoke 覆盖 34 个页面、8 个运行接口、4 个投影及 364 份小说图片。
- 实验过程中发现上游旧图漂移。双轴审查阻止了“为了让构建通过而顺手发布新研究内容”，最终改为冻结批准投影并隔离未审变化。

## 这套方法真正改善了什么

1. **先锁边界，再优化代码。** 最大收益不是少写代码，而是审查能指出“构建修好了，但研究内容越界了”。
2. **把测试 seam 说清楚。** 真实 HTTP 合同比直接测 handler/helper 更能保护重构。
3. **让接口以调用者为中心。** 完整 `RequestListener` 比 `handled: boolean` 更难被遗漏 fallback 或安全头。
4. **把完成条件量化。** 95 分说明实验成功，但也诚实保留 TDD 粒度和内部文件夹具的扣分。
5. **把部署授权与可部署性分开。** 能构建、能本地 smoke，不等于获准发布。

## 下次应改进

- 每个纵向 TDD slice 坚持“一条红灯 → 最小实现 → 一次绿灯”，不要把三个接口测试一起写完。
- 提前提供一个测试夹具，只管理真实端口、临时目录和服务器生命周期；不把生产存储抽象成假 port。
- 在开始实现前记录所有外部输入的摘要。若工作期间上游改变，立即进入“冻结/重新授权”门禁。
- 代码审查固定点应选“规格完成、实现未开始”的提交；本次 `0d4362e` 证明合适。
- 对非阻断 smell 明确“修复 / 接受 / 延后触发条件”，避免审查报告变成无人负责的愿望清单。
